Tolerant comparisons

Grid geometry is full of points that ought to sit exactly on a boundary and, in floating point, do not. Every predicate in this package therefore compares up to a relative tolerance of about 1000 * eps, rather than exactly.

julia> using GridGeometryUtils

julia> inside(Point(1.0, 0.0), Circle((0.0, 0.0), 1.0))   # exactly on the boundary
true

The tolerance

GridGeometryUtils.isequal_r is the primitive the rest is built on. Two properties matter:

  • It is symmetric: isequal_r(a, b) == isequal_r(b, a) for all a and b. A relative difference taken against just one operand is not.
  • Its tolerance is relative to the larger operand, so it means the same thing whatever the scale of the geometry, rather than being tuned for coordinates near 1.

Near zero there is no meaningful relative scale, so operands that are both within an absolute 1000 * eps of zero compare equal; GridGeometryUtils.isquasizero is that test on its own.

The ordering comparisons GridGeometryUtils.lt_r and its siblings follow from it: values that compare equal are neither strictly less nor strictly greater, and are both ≤ and ≥.

The @comp macro

GridGeometryUtils.@comp rewrites every comparison operator in an expression into its tolerant counterpart, which is how the predicates stay readable:

julia> using GridGeometryUtils: @comp

julia> x = 0.1 + 0.2;

julia> x == 0.3
false

julia> @comp x == 0.3
true

julia> @comp 0.0 ≤ x ≤ 0.3     # chained comparisons work too
true

The rewrite covers ==, !=, ≠, <, >, <=, ≤, >= and ≥, in both their ASCII and Unicode spellings. === and !== are deliberately left alone: they test identity, not numeric value.

The rewrite is purely syntactic and reaches every level of the expression, so an operator used as a value — filter(==(x), v) — is rewritten as well. It expands to fully qualified references, so @comp works from any module without importing the comparison functions it produces.

Reference

GridGeometryUtils.isequal_r — Function
isequal_r(a, b) -> Bool

Test a == b up to a relative tolerance of 1000 * eps. Operands that are both within an absolute 1000 * eps of zero compare equal, since no relative scale is meaningful there.

Unlike a bare relative difference, this is symmetric: isequal_r(a, b) == isequal_r(b, a) for all a and b.

GridGeometryUtils.isquasizero — Function
isquasizero(a) -> Bool

Test whether a is within an absolute 1000 * eps of zero. The tolerance is absolute rather than relative because no relative scale is meaningful near zero.

GridGeometryUtils.neq_r — Function
neq_r(a, b) -> Bool

Negation of isequal_r: a and b differ by more than round-off.

source
GridGeometryUtils.lt_r — Function
lt_r(a, b) -> Bool
gt_r(a, b) -> Bool
leq_r(a, b) -> Bool
geq_r(a, b) -> Bool

Ordering comparisons that treat operands within round-off of each other as equal, as isequal_r does: lt_r and gt_r are the strict < and >, leq_r and geq_r their non-strict counterparts. Values that compare equal are therefore neither lt_r nor gt_r, and both leq_r and geq_r.

These are what @comp rewrites comparison operators into.

source
GridGeometryUtils.@comp — Macro
@comp expr

Rewrite every comparison operator in expr into its round-off-tolerant counterpart, so == becomes isequal_r, < becomes lt_r, ≤ becomes leq_r, and so on.

The rewrite is purely syntactic and reaches every level of expr, so an operator used as a value (filter(==(x), v)) is rewritten too. === and !== are left alone.

Examples

julia> using GridGeometryUtils: @comp

julia> x = 0.1 + 0.2;

julia> x == 0.3
false

julia> @comp x == 0.3
true

GridGeometryUtils.cross2 — Function
cross2(u, v) -> Number

$z$ component of the cross product of two 2-D vectors, i.e. the signed area of the parallelogram they span. It vanishes exactly when u and v are parallel.

source
cross2(a, b, c) -> Number

cross2 of b - a and c - a; twice the signed area of the triangle (a, b, c). Its sign gives the direction of the turn a → b → c.

source
GridGeometryUtils.areparallel — Function
areparallel(u, v) -> Bool

Test whether the 2-D direction vectors u and v are parallel, up to round-off.

The test is on the angle between them, not on cross2 directly: since cross2(u, v) == norm(u) * norm(v) * sin(θ), dividing by the norms gives a scale-free tolerance, where an absolute threshold on cross2 would call any sufficiently small geometry parallel. Throws an ArgumentError for a zero-length vector, which has no direction to compare.

GridGeometryUtils.coords — Function
coords(p) -> SVector

Coordinates of p as a plain vector, whether p is a Point or already an SVector. Predicates accept both forms (QueryPoint), so anything doing vector arithmetic on a query point goes through this rather than reaching for the p field.

source
GridGeometryUtils.QueryPoint — Type
QueryPoint{N}

A point in N dimensions supplied to a predicate or query, in either accepted form: a Point or a bare SVector. Use coords to get at its coordinates.

GridGeometryUtils.rotation_matrix — Function
rotation_matrix(sinθ, cosθ) -> SMatrix{2, 2}

Matrix rotating a 2-D vector clockwise by the angle whose sine and cosine are given; its transpose rotates counter-clockwise.

Shapes store their vertices already rotated counter-clockwise by θ, so a containment test applies this matrix to bring a query point back into the shape's own frame.
